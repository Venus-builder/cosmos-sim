# 宇宙シミュレーター 第3・4段階 設計書(生命と文明)

作成日: 2026-11-03 / 状態: レビュー待ち(未実装)

前提: 第1段階(宇宙全体のN体計算と時間操作)と第2段階(銀河→恒星系→惑星へのズーム、太陽系は実データ)は実装済み。
本書は「生き物が生まれ、増減し、進化し、知的生命体や文明ができる」ところまでの設計。

## 0. 大原則 — 何が本物で、何が仮説か

| 区分 | 内容 | 扱い |
|---|---|---|
| 物理(本物の式) | 重力、膨張、恒星の進化、放射平衡、ケプラー運動、大気の散逸、潮汐固定、隕石衝突の頻度 | 既知の式と実測値を使う |
| 実データ | 太陽系・地球の軌道と物理量、現在の人類の統計(人口、CO₂ 濃度、エネルギー消費など) | 出典つきの表にして入れる |
| 確率モデル(仮説) | 生命の誕生、進化の分岐、知性の出現、文明の盛衰 | 乱数で動かす。**予測ではなく思考実験**と明示する |

- 「生命がどう生まれたか」は物理法則から導けない(観測例は地球の1つだけ)。したがって第3・4段階は、本物の物理が作る**環境**の中で、確率モデルが**生命と文明**を動かす二層構造にする。
- 結果は毎回変わる。シード値を表示し、同じ値を入れれば再現できる。「毎回違う宇宙」と「同じ宇宙を再実験」の両方を選べる。
- 画面とデータには、確率モデル由来の値に「仮説」の印を付ける。「人類の未来の予測」とは表示しない。

## 1. 第3段階: 生命

### 1.1 惑星の環境の時間変化(物理層)
各惑星について、宇宙時間 t ごとに次を計算する。
- 恒星の光度の増加(主系列で年約 1% / 100 Myr の増光)と、それによる平衡温度 T_eq = 278.5 K · L^¼ · a^-½ · (1-A)^¼
- 温室効果(大気量に依存)と、炭酸塩・ケイ酸塩サイクルによる気温の自己調整(地球型で働く簡略モデル)
- 液体の水が存在できる期間(表面温度 273〜373 K、大気圧が三重点以上)
- 大気の保持(ジーンズ・パラメーター、恒星風と磁場による剥ぎ取り)
- 潮汐固定(軌道半径と恒星質量から固定時間を計算。固定されると昼夜側で気候が分かれる)
- 重爆撃期、隕石衝突(大きさ別の頻度: べき乗則)、近傍の超新星・ガンマ線バーストによる絶滅圧
- 恒星の寿命(質量から計算)。寿命が尽きるとその恒星系の生命は終わる

### 1.2 生命の段階(確率層)
段階を有限状態機械として扱い、遷移は「ハード・ステップ」モデルに従うポアソン過程とする。

`なし → 前生物化学 → 単純な生命 → 酸素発生型光合成 → 真核生物 → 多細胞 → 複雑な生態系 → 神経系 → 知性`

- 各遷移の発生率は、環境の条件(水、温度、エネルギー、元素の量)で変わる。条件が悪い間は率が 0。
- 発生率の基準値は文献のばらつきが大きい。**パラメーターとして露出**し、UIのスライダーで変えられるようにする(例: 「生命が生まれやすい宇宙」「極めて稀な宇宙」)。
- 地球の実績(約 40 億年前に単純な生命、約 24 億年前に酸素、約 5.4 億年前に多細胞の爆発的増加)を「標準シナリオ」として載せ、一般の惑星はそれを基準に率を決める。

### 1.3 個体群と進化(エージェント層)
生態系は「種の集まり」として抽象化する(個体は追わない)。
- 各種は、形質ベクトル(大きさ、代謝、移動、感覚、社会性、…)と個体数を持つ。
- 毎ステップ: 増減(ロジスティック+捕食・競合)、形質の変異(ランダムウォーク+自然選択の勾配)、種分化、絶滅。
- 環境の急変(衝突、氷河期、酸素の増減)では、形質に応じて絶滅率が変わる。
- 系統樹を保存し、UI で系統樹と「生物の総量」の時系列が見られる。

### 1.4 見た目
- 生命がいる惑星は、海や陸の色が変わる(緑、赤い藻、白い雲の増加)。酸素が増えると大気が青くなる。
- 地表ズームでは、種の形質ベクトルから**手続き生成した生き物**の姿を表示する(第3段階の後半。実在の生物の再現ではないと明記)。

## 2. 第4段階: 知的生命と文明

### 2.1 知性の出現
- 神経系・社会性・道具の使用などの形質が閾値を超える確率として扱う。
- 出現しない惑星も多い(出現率はパラメーター)。出現しても、その時点での環境次第で滅びる。

### 2.2 文明モデル(エージェントベース)
単位は「集団(部族・国家)」。個々の人間は追わない。
- 状態: 人口、エネルギー消費、技術水準(技術の木)、資源、環境負荷、文化・結束
- 技術の木: 農耕、文字、金属、印刷、蒸気、電力、情報、核、宇宙、AI…の依存関係グラフ。各技術は確率的に発見される。
- 環境との相互作用: CO₂ と気温の負帰還・正帰還、資源の枯渇、土壌劣化、疫病
- 集団間の相互作用: 交易、同盟、戦争、技術拡散
- 結果として、繁栄、停滞、崩壊、持続可能な定着、宇宙への進出などの分岐が出る。何が起きたかを「年表」として記録する(教訓として読み返せる)。
- 「何かを生み出したら」(AI など)は、技術の木のノードとして扱い、その後の社会モデルへの影響を数値パラメーターで与える。中身は仮説。

### 2.3 「いまの世界」の再現
- 地球は第2段階で実データの軌道・物理量が入っている。第4段階で、現在の統計(人口約 81 億、大気 CO₂ 約 420 ppm、気温偏差、エネルギー消費、…)を**初期条件**として入れる。
- そこから確率モデルで先に進める「もしもの実験」にする。予測ではなく、条件を変えて比較するためのもの。出典と取得日を表に記録する。

## 3. 時間の扱い

- 生命・進化の時間は Myr〜Gyr 単位。宇宙の時計と同じ速度スライダー(対数)で動かす。
- 文明の時間は年〜千年単位。文明が出現したら、時計の刻みを自動で細かくする(「文明モード」)。
- 逆再生はこの層では**しない**(確率過程の逆戻しは意味がない)。代わりに「この時点のスナップショット」を保存して戻れるようにする。

## 4. 構成

| ファイル | 役割 | テスト |
|---|---|---|
| `astro.js`(既存) | 恒星・惑星・銀河の生成と物理 | node で自動テスト |
| `life.js`(新規) | 惑星環境の時間変化、生命段階、種の進化 | シード固定の決定性、統計テスト(平均発生時間など) |
| `civ.js`(新規) | 知性の出現、文明モデル、技術の木 | 保存則、既知の簡単な場合の解析解との一致 |
| `scenes.js`(既存) | 描画。惑星の色・大気の変化、生物の表示、系統樹・年表パネル | ブラウザで目視 |
| `data/` | 現在の人類統計など実データ(出典つき CSV/JSON) | 出典欄の存在チェック |

- 状態の保存: シードと設定、スナップショット(JSON)。ブラウザの localStorage に保存し、必要なら書き出し/読み込み。
- 計算量: 1つの惑星の生態系・文明だけを詳細に回す(見ている惑星)。それ以外は確率の期待値で粗く進める(遅延評価)。見に行った時点で、その惑星の過去を乱数から再構成する。

## 5. 実装の順番(マイルストーン)

1. **3a**: 惑星の環境の時間変化と「生命が可能だった期間」の表示(物理層だけ)
2. **3b**: 生命の段階遷移(確率層)と、惑星の見た目の変化
3. **3c**: 種の進化(系統樹)と絶滅イベント
4. **3d**: 生き物の手続き生成と地表ズーム
5. **4a**: 知性の出現と最小の文明モデル(人口・エネルギー・技術)
6. **4b**: 技術の木と環境の相互作用、年表
7. **4c**: 現在の地球を初期条件にしたシナリオ実験

## 6. リスクと未決事項

- 生命・文明のパラメーターは根拠が弱い。**探索的な実験**として使い、断定的な表現を避ける。
- 文明モデルは単純化が大きく、実在の社会を再現しない。
- 計算の重さは、スマホで特に問題になる可能性が高い。見ている惑星だけ詳細に回す設計で抑える。
- 生き物の見た目の作り込みは、品質のばらつきが大きい。第3段階の後半に回す。
- 人類の統計の取得と更新は、出典の確認が必要(自動取得はせず、手で入れた表を使う)。

## 7. 決定事項(2026-11-03)

1. 最初に作るのは 3a(惑星の環境の時間変化)。→ **実装済み**(`life.js`)
2. 生命の生まれやすさの標準値は、地球の実績に合わせる。
3. 文明モデルは**個人単位**にする。

### 個人単位にする場合の設計メモ(第4段階)
- 地球全体の80億人を個別に計算するのは不可能。**注目する集団(数百〜数万人)だけを個人として詳細に動かし、その外側は統計量(人口・資源)で粗く扱う**。注目する集団は、ユーザーが選んだ場所に切り替えられる。
- 個人の状態: 年齢、性別、健康、スキル、記憶(知っている技術)、関係(家族・友人・協力/敵対)、所持資源、価値観
- 行動: 採集・生産・交易・学習・繁殖・移動・争い。意思決定は、欲求(空腹、安全、社会的承認)の効用最大化+ランダム性
- 世代交代と遺伝・文化の伝達(技術は人から人へ伝わり、人が死ぬと失われうる)
- 創発として、分業・国家・宗教・戦争・発明が現れるかを観察する(設計で与えず、ルールから出るようにする)
- 計算量の目安: 数千エージェントを毎ステップ更新できるよう、空間ハッシュと粗い時間刻みを使う
